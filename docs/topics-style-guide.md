# 專題（Topics）Style Guide

目的只有一個：**讓每一篇專題看起來是同一個網站做的。**
撰寫流程見 [`content/topics/README.md`](../content/topics/README.md)。

## 1. 兩層結構

| 層                                               | 放哪                     | 誰用       | 誰決定外觀            |
| ------------------------------------------------ | ------------------------ | ---------- | --------------------- |
| **共用積木**（每篇都會用到的內容區塊）           | `components/topics/`     | 所有專題   | 這裡改一次，全部同步  |
| **單篇專屬的互動元件**（模擬器、探索器、視覺化） | `content/topics/<slug>/` | 只有那一篇 | 必須套用第 4 節的規則 |

視覺一致性來自「積木共用」＋「專屬元件只用同一套 token」。

## 2. 共用積木：先用現成的，不要自己發明

| 你想表達的                         | 用這個                                | 不要這樣做                             |
| ---------------------------------- | ------------------------------------- | -------------------------------------- |
| 值得讀者停下來的一句話             | `<Callout>…</Callout>`                | 自己包 `<div>` 加背景色                |
| 兩種做法／想法的對照（❌ vs ✅）   | `<Compare bad={…} good={…} />`        | 手寫兩欄表格                           |
| 真的需要清單的場合（步驟、檢查表） | `<KeyTakeaways items={[…]} />`        | 純 Markdown 清單；也不要拿它當文章結尾 |
| 讓讀者自我檢驗的單選題             | `<Quiz question="…" options={[…]} />` | 每篇各寫一個測驗元件                   |

用法範例：`content/topics/how-to-learn-a-new-concept/index.mdx`。

**使用節制**：`Callout` 一篇不超過 3–4 個，多了就沒有「停下來」的效果。

### 什麼時候可以新增共用積木

當**第二篇**專題也需要同一種區塊時，把它提升到 `components/topics/`，並在上表補一列。
第一次出現時先放在該篇資料夾裡，不要預先抽象。

## 3. 排版與色調：宋體、紙色、單欄

專題與一般文章的區隔來自三件事，全部在 `.topic-shell`（`app/globals.css`）與 `TopicHeader` 裡：

| 項目     | 專題                                                                                                                 | 一般文章               |
| -------- | -------------------------------------------------------------------------------------------------------------------- | ---------------------- |
| 正文字體 | **宋體**（Noto Serif TC，`next/font` 載入，變數 `--font-serif-tc`）                                                  | 黑體（Inter + 系統字） |
| 色調     | 淺：紙色底 `#faf9f6`／墨色字 `#1f1d1a`；深：墨底 `#1a1917`／米白字 `#e9e5dc`。**跟著全站的淺／深切換走，不強制深色** | 全站預設黑白           |
| 版面     | **單欄置中**，行長 32 字，沒有側欄                                                                                   | 兩欄＋側欄目錄         |
| 標題區   | 「專題」小字標 → 宋體大標 → 描述 → 日期・閱讀時間 → 章節列表 → 細線                                                  | 標題＋日期             |
| 章節導覽 | 標題區內的章節列表（只列 `##`），一開始看到全貌、可跳；閱讀中不再有東西跟著捲                                        | sticky 目錄            |

### 三種字體各司其職

| 內容                            | 字體 | 怎麼指定                                                         |
| ------------------------------- | ---- | ---------------------------------------------------------------- |
| 正文、標題、引言                | 宋體 | `.topic-article` 預設；`.not-prose` 區塊想用宋體加 `topic-serif` |
| 互動元件、Quiz、表格、按鈕等 UI | 黑體 | `.not-prose` 自動回到 `--font-sans`，不用做事                    |
| 程式碼                          | 等寬 | `code`／`pre` 預設                                               |

技術類專題裡的程式碼、表格、互動元件本來就是黑體／等寬，跟宋體正文並排反而對比更清楚。

### 正文數字

| 項目               | 值                                                             | 為什麼                                        |
| ------------------ | -------------------------------------------------------------- | --------------------------------------------- |
| 字級 / 行距 / 字距 | `1.15625rem`（=18.5px）/ `2.05` / `0.01em`                     | 宋體本身有筆畫粗細撐節奏，字距只需微量        |
| 行長               | `32em`（約 32 字）                                             | 中文長文的舒適區是每行 30–38 字               |
| 段距               | `0.5em`（小於行距）                                            | 段距 ≈ 行距時每句都像獨立條目；壓小才連成論述 |
| 標題前空白         | `h2` 上方 3.6em、`h3` 上方 2.6em                               | 層次交給空白                                  |
| 引言（`Callout`）  | 上方細線、左縮排、`1.5rem`、600、懸掛標點（`-indent-[0.5em]`） | 排版診斷的宋體版；不畫灰底、不畫粗色條        |
| 次要資訊           | `text-muted-foreground`（紙色系裡是偏暖的灰）                  | 日期、圖說、說明文字                          |

**尺寸只用 `rem`／`em`，不用 `px`**：容器、斷點都是 rem，讀者調大瀏覽器字級時正文要跟著放大。

### 色調的實作方式

`.topic-shell` 覆寫 shadcn 的 token 三元組（`--background`、`--foreground`、`--muted`、`--border`…），**並在同一個元素上重新宣告 `--color-*`**。Tailwind v4 的 `bg-background`、`text-muted-foreground` 讀的是 `--color-*`，而那些在 `:root` 上就算好了，只改三元組不會生效——這是唯一容易踩的坑。`.dark .topic-shell` 只換三元組。

### 框線的使用

- **內容型積木不畫框**：`Callout`、`Compare`、`KeyTakeaways` 只靠間距與字級分隔。
- **可操作的區塊才有框**：`Quiz` 與互動元件用 1px `border` 細線框，**沒有底色**；內部結果區也是細線，不疊底色。

### 排版救不了的事

一句一段、句長全部一致，是寫作層的問題，換排版不會消失。寫作時把同一個意思的幾句併回同一段；**文末用段落收尾，不用條列**。

## 4. 單篇專屬互動元件的規則

- **只用既有的設計 token 與 UI 元件**：`@/components/ui/*`（`Button`、`Card`、`Badge`…）與 Tailwind 的語意 class（`border`、`bg-background`、`text-muted-foreground`）。
- **不寫死顏色**：不出現 `#hex`、`bg-blue-500`、`text-red-600` 這類；需要「好／壞」「高／低」的語意色時，用粗細／圖示區分，或用 `destructive` token。深色模式與未來改版才不會壞。
- **外層容器固定**：`className="not-prose my-[3.5em] rounded-lg border p-6 md:p-8"`（細線框、無底色），讓所有互動區塊在文章裡的份量一致。
- **一定有小標**：`<p className="text-sm font-medium text-muted-foreground">` 說明「這是什麼、要讀者做什麼」。
- **結果區塊加 `aria-live="polite"`**，讓螢幕閱讀器知道數字變了。
- **控制項用原生元素**：`<input type="range">`、`<input type="checkbox">`、`<button>`（或 `Button`），不引入新的 UI 套件。
- **一個元件只講一個道理**。要講兩件事，就拆成兩個元件。
- **每個互動元件都要有測試**：純計算抽成獨立函式單獨測；UI 用 Testing Library 測「操作後畫面怎麼變」。

## 5. 排版與樣式改哪裡

- 專題區的排版、標題間距、程式碼區塊配色：`app/globals.css` 最底下的 `.topic-shell` 區塊。**只改這裡**，不要在單篇裡覆寫。
- 共用積木的外觀：對應的 `components/topics/*.tsx`。
- 專題區需要跟一般文章不同的視覺風格時，也是在 `.topic-shell` scope 內處理，不會外溢到 `/posts`。

## 6. 目前刻意不做的

- 強制深色、動畫、圖表函式庫。色調與字體已定（紙色＋宋體），要調整只改 `.topic-shell` 與共用積木。
- `cover` 欄位已定義但尚未在畫面上渲染。
